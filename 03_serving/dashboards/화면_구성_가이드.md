# 대시보드 화면 구성 가이드 (카드 5-G, 와이어프레임 기준)

와이어프레임(판매·환불 2페이지)의 구성을 그대로 따른다. 저장소의 `commerce_poc.lvdash.json`은 `build_dashboard.py`가 만든 개편안이며 **Databricks에서 열어 확인하지 못했다(미검증)**. 열리지 않거나 모양이 다르면 3절로 화면에서 직접 만든다. 데이터셋 SQL은 로컬 테스트(sqlite, 손계산 기대값)를 통과했지만 Spark에서 실행되는 것은 확인하지 못했다.

## 1. 실행 순서 (Databricks)

1. 저장소를 커밋·푸시하고 Databricks Git folder에서 **Pull**한다.
2. Gold가 최신이 아니면 `02_pipeline/gold/run_gold.py`를 실행한다 (`check_gold` 통과 확인).
3. **`03_serving/metric_views/run_metric_views.py`를 반드시 다시 실행한다.** 두 Metric View에 `payment_week`(결제주)가 추가되었다. 실행 뒤 `check_metric_views` 결과가 `OK`여야 한다.
4. 확인 쿼리: `SELECT payment_week, MEASURE(total_sales) FROM commerce_poc.serving.sales_metrics GROUP BY ALL ORDER BY 1` 이 월요일 날짜를 주마다 한 줄씩 내야 한다.
5. `03_serving/dashboards/commerce_poc.lvdash.json`을 열어 본다. 안 열리면 3절부터 따라 한다.

## 2. 구성 (와이어프레임)

- **필터(전역):** 채널(다중, 기본 전체), 카테고리(다중, 기본 전체), 조회 기간(결제일, 기본 최근 30일). 비교 기간(직전 같은 길이 · 전년 동기)은 자동이며 입력받지 않는다. 화면 표시는 첫 카드의 설명 글(`비교 기간(자동)…`)로 둔다.
- **판매 페이지:** 큰 카드 3개(총판매금액이 가장 크다, 순판매금액, 환불금액비율) → 작은 카드 5개(결제고객수, 객단가, 상품결제건수, 상품결제단가, 환불금액) → 채널별 총판매금액 추이(주별 선, 채널 3개) → [채널별 순판매금액 비중 | 환불금액비율 추이(주별)] → [결제수단별 | 카테고리별 총판매금액 막대(큰 순, 비중 %)] → 채널별 지표 표.
- **환불 페이지:** 큰 카드 3개(환불금액, 환불수량, 환불금액비율) → [사유별 환불금액(큰 순·비중) | 채널별 환불금액비율(큰 순)] → 결제일별 환불금액 추이(원결제일 귀속·주별) → 사유별 환불 상세 표.
- **KPI 카드 하나 = 값 위젯 + 바로 아래 증감 위젯.** 값은 `…_text`(예 `10,000원`), 증감은 `…_delta`다.
  - 큰 카드: `▲ 12.3% 직전 기간 대비 · 전년 동기: ▼ 5.0%` (환불금액비율은 `▲ 0.5%p 직전 기간 대비`, 전년 동기 줄 없음).
  - 작은 카드: `▲ 12.3%`.
  - 비교 기간에 상품결제건수가 0이면 `직전 기간: 실적이 없습니다.` / `전년 동기: 실적이 없습니다.` (작은 카드는 `실적이 없습니다.`). 비교값이 0이거나 없으면 `-`. 상태 색(초록·빨강)은 쓰지 않는다.
- 채널 색은 모든 차트에서 고정: 자사몰 `#2a78d6`, 종합 오픈마켓 `#eb6834`, 스포츠 전문몰 `#1baf7a`. 채널이 아닌 단일 계열은 `#5b6573`.

## 3. 화면에서 직접 구성

### 3-1. 데이터셋 매개변수

모든 데이터셋에 같은 이름·형식의 매개변수를 만든다 (이름이 같아야 전역 필터 하나가 데이터셋 전체에 걸린다).

| 매개변수 | 유형 | 기본값 |
|---|---|---|
| `date_range` | 날짜 범위 | `now-30d/d` ~ `now/d` (상대 날짜) |
| `channels` | 다중 선택 문자열 | 자사몰, 종합 오픈마켓, 스포츠 전문몰 (전체) |
| `categories` | 다중 선택 문자열 | 가방, 신발, 액세서리, 의류, 캠핑·등산 장비 (전체) |

### 3-2. 데이터셋 SQL (그대로 붙여 넣는다)

쉬운 것(`sales_by_category`)부터 넣어 매개변수가 동작하는지 먼저 확인하고, `sales_kpi`·`refund_kpi`는 마지막에 넣는다 (CTE 안에서 `MEASURE()`를 여러 번 조회하는 구조라 Databricks에서 처음 돌려 본다).

| 항목 | 기대 | 안 될 때 |

## 4. 알려진 한계

- 조회 기간 끝이 오늘이면 오늘은 하루가 다 차지 않아 증감이 낮게 나올 수 있다.
- 데이터가 2025-10-15부터라 조회 기간이 1년 전으로 가면 전년 동기는 `실적이 없습니다.`로 보인다.
- 값·증감은 쿼리에서 만든 문자열이라 정렬·합산에 쓸 수 없다 (숫자 열은 같은 데이터셋에 `지표` 이름으로 있다).
- 와이어프레임은 큰 카드 비율이 2:1:1이지만 격자가 6칸이라, 총판매금액 카드를 왼쪽 절반으로 두고 나머지 둘을 오른쪽에 위아래로 쌓았다.
- CTE 구조의 `MEASURE()` 조회가 실패하면 오류 문장을 알려 주면 기간별 쿼리로 나눈다.
