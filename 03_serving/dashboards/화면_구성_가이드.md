# 대시보드 화면 구성 가이드 (3페이지: 전체 요약 · 마케팅 개선 · 밸류체인 개선)

이 문서는 Databricks 화면에서 위젯을 **직접** 만들고 유지보수하기 위한 설명서다. 이전 판(판매·환불 2페이지), 대시보드 JSON, 생성기(`build_dashboard.py`, `dashboard_spec.py`)와 그 테스트는 삭제했고 git 커밋 `beba3ef`(스냅샷)에 있다. 화면이 정본이다.
아래 SQL은 삭제 전 로컬 테스트가 검증한 쿼리 만들기 함수(`dashboard_spec.py`)로 만든 것이다. **새로 추가한 데이터셋(`*_by_product`, `*_by_hour`)과 `products` 필터는 Databricks에서 확인하지 않았다 (미검증).**

## 1. 읽는 법: 위젯 하나는 어떻게 만들어지나

`Metric View`(지표 정의) → **데이터셋**(SQL, `MEASURE()`로 지표 조회) → **위젯**(어떤 열을 어떤 축에 놓을지) → **선택기**(매개변수로 데이터셋의 WHERE에 걸린다).

- 지표를 바꾸고 싶다 → 데이터셋 SQL의 `MEASURE(지표)`를 바꾼다 (지표 목록은 아래 5절).
- 보여 주는 기준을 바꾸고 싶다(예: 주별 → 일별) → 데이터셋 SQL의 기준 열(`payment_week` → `payment_date`)을 바꾸고 위젯 X 필드를 맞춘다.
- 모양만 바꾸고 싶다 → 위젯 설정(종류, 색, 정렬, 서식)만 만진다. 데이터는 그대로다.
- 필터 → 데이터셋의 **매개변수**(이름이 같아야 선택기 하나가 데이터셋 여러 개에 걸린다).
- 이미 집계된 행을 화면에서 다시 거르면 결제고객수·객단가·비율이 틀리므로, 거르기는 반드시 매개변수(WHERE)로 한다.

### 데이터셋 이름 규칙
`sum_` = 전체 요약 페이지, `mkt_` = 마케팅 개선 페이지, `val_` = 밸류체인 개선 페이지. 같은 쿼리여도 페이지마다 데이터셋을 따로 만든다(전체 요약은 기간만 걸고, 나머지는 채널·카테고리·상품도 건다).

## 2. 사전 준비
1. Gold가 최신이 아니면 `02_pipeline/gold/run_gold.py` 실행 (`check_gold`가 비어 있어야 한다).
2. `03_serving/metric_views/run_metric_views.py` 실행 (`check_metric_views`가 비어 있어야 한다).
3. 확인: `SELECT payment_week, MEASURE(total_sales) FROM commerce_poc.serving.sales_metrics GROUP BY ALL ORDER BY 1`
4. 시간대 위젯은 `payment_hour`가 Metric View에 있어야 한다. 정의는 구현했지만(`metric_defs.py`) Databricks의 Metric View에는 `run_metric_views.py`를 다시 실행해야 반영된다 (미검증).

## 3. 페이지 구성

| 페이지 | 이름 | 선택기 | 내용 |
|---|---|---|---|
| 0 | 전체 요약 | 조회 기간, 비교 기간 | 모든 채널 통합 운영 현황: 핵심 숫자, 기간 대비 표, 채널별 추이·비중 |
| 1 | 마케팅 개선 | 채널, 카테고리, 상품, 조회 기간, 비교 기간 | 채널·결제수단·카테고리·상품·(시간대)별 매출 드릴다운 |
| 2 | 밸류체인 개선 | 같은 5개 | 환불 사유·채널·상품별 환불 드릴다운 |

- 이름은 후보다. 바꾸려면 페이지 탭 이름만 고친다.
- 객단가: 전체 요약은 필터가 없어 "전체 구매고객 1인당 매출"이다. 마케팅 페이지에서 카테고리·상품을 고르면 "그것을 산 고객 1인당 매출"이 되어 의미가 달라지므로 카드 이름을 다르게 둔다. 객단가는 비가산 지표라 카테고리별 값을 더하면 안 된다 (명세 6.5절).
- 채널 색은 모든 차트에서 고정: 자사몰 `#2a78d6`, 종합 오픈마켓 `#eb6834`, 스포츠 전문몰 `#1baf7a`. 채널이 아닌 단일 계열은 `#5b6573`.

## 4. 매개변수

| 매개변수 | 유형 | 기본값 | 쓰는 페이지 |
|---|---|---|---|
| `date_range` | 날짜 범위 | `now-30d/d` ~ `now/d` | 전체 |
| `compare_range` | 날짜 범위 | `now-61d/d` ~ `now-31d/d` | 비교 표 데이터셋만 |
| `channels` | 다중 선택 문자열 | 자사몰, 종합 오픈마켓, 스포츠 전문몰 | 1·2페이지 |
| `categories` | 다중 선택 문자열 | 가방, 신발, 액세서리, 의류, 캠핑·등산 장비 | 1·2페이지 |
| `products` | 다중 선택 문자열 | 상품 15개 전체 (`dim_product.product_name`) | 1·2페이지 |

다중 선택 필터는 `array_contains(:param, 열)`로 건다. `IN (:param)`은 모든 데이터셋을 실패시켜서 쓰지 않는다 (2026-10-14 확인).

## 5. 지표 사전 (Metric View에 있는 것)

| 지표(MEASURE) | 의미 | 뷰 |
|---|---|---|
| `total_sales` | 총판매금액 (결제 성공 상품의 할인 후 금액 합) | sales_metrics |
| `refund_amount` | 환불금액 | sales_metrics(판매 기준) / refund_metrics(환불 분석) |
| `net_sales` | 순판매금액 = 총판매금액 − 환불금액 | sales_metrics |
| `refund_ratio` | 환불금액비율 = 환불금액 ÷ 총판매금액 | sales_metrics |
| `item_count` | 상품결제건수 (상품 행 수, 수량 합이 아니다) | sales_metrics |
| `unit_price_per_item` | 상품결제단가 | sales_metrics |
| `paying_customers` | 결제고객수 (channel+user_id distinct) | sales_metrics |
| `average_order_value` | 객단가 = 총판매금액 ÷ 결제고객수 | sales_metrics |
| `refund_quantity` | 환불수량 | refund_metrics |

분석 기준(dims): `payment_date`, `payment_week`, `channel_name`, `product_name`, `category`, `method_name`(sales_metrics) / `refund_reason`, `refund_type`, `refund_date`(refund_metrics). 판매 수량 합계 지표와 결제 성공률·취소율은 아직 없다.

## 6. 페이지 0: 전체 요약

### 데이터셋 (기간만 건다)

**`sum_sales_kpi`** — KPI 카드 8개 숫자

- 뷰: `sales_metrics` / 분석 기준: 없음 / 지표: total_sales, net_sales, refund_ratio, paying_customers, average_order_value, item_count, unit_price_per_item, refund_amount
- 위젯이 쓰는 열: total_sales, net_sales, refund_ratio, paying_customers, average_order_value, item_count, unit_price_per_item, refund_amount

```sql
SELECT MEASURE(total_sales) AS total_sales, MEASURE(net_sales) AS net_sales, MEASURE(refund_ratio) AS refund_ratio, MEASURE(paying_customers) AS paying_customers, MEASURE(average_order_value) AS average_order_value, MEASURE(item_count) AS item_count, MEASURE(unit_price_per_item) AS unit_price_per_item, MEASURE(refund_amount) AS refund_amount FROM commerce_poc.serving.sales_metrics WHERE payment_date BETWEEN :date_range.min AND :date_range.max
```

**`sum_refund_kpi`** — 환불수량 카드

- 뷰: `refund_metrics` / 분석 기준: 없음 / 지표: refund_amount, refund_quantity
- 위젯이 쓰는 열: refund_quantity

```sql
SELECT MEASURE(refund_amount) AS refund_amount, MEASURE(refund_quantity) AS refund_quantity FROM commerce_poc.serving.refund_metrics WHERE payment_date BETWEEN :date_range.min AND :date_range.max
```

**`sum_sales_compare`** — 조회 기간 · 비교 기간 대비 표(판매)

- 위젯이 쓰는 열: metric, current_value, compare_value, change

**`sum_sales_trend_by_channel_week`** — 채널별 총판매금액 주별 선 차트

- 뷰: `sales_metrics` / 분석 기준: payment_week, channel_name / 지표: total_sales
- 위젯이 쓰는 열: payment_week, channel_name, total_sales

```sql
SELECT payment_week, channel_name, MEASURE(total_sales) AS total_sales FROM commerce_poc.serving.sales_metrics WHERE payment_date BETWEEN :date_range.min AND :date_range.max GROUP BY ALL ORDER BY payment_week, channel_name
```

**`sum_channel_net_share`** — 채널별 순판매금액 비중 막대

- 뷰: `sales_metrics` / 분석 기준: channel_name / 지표: net_sales
- 위젯이 쓰는 열: channel_name, net_sales, net_sales_share

```sql
SELECT *, CAST(net_sales AS DOUBLE) / SUM(net_sales) OVER () AS net_sales_share FROM (SELECT channel_name, MEASURE(net_sales) AS net_sales FROM commerce_poc.serving.sales_metrics WHERE payment_date BETWEEN :date_range.min AND :date_range.max GROUP BY ALL) AS base ORDER BY net_sales DESC, channel_name
```

**`sum_refund_ratio_by_week`** — 환불금액비율 주별 선 차트

- 뷰: `sales_metrics` / 분석 기준: payment_week / 지표: refund_ratio
- 위젯이 쓰는 열: payment_week, refund_ratio

```sql
SELECT payment_week, MEASURE(refund_ratio) AS refund_ratio FROM commerce_poc.serving.sales_metrics WHERE payment_date BETWEEN :date_range.min AND :date_range.max GROUP BY ALL ORDER BY payment_week
```

### 위젯

| 위젯 | 종류 | 데이터셋 | 필드 설정 | 위치 x,y 폭×높이 | 바꾸려면 |
|---|---|---|---|---|---|
| 선택기: 조회 기간 (결제일) | filter (Date range) | - | Parameter: `date_range`. 연결 데이터셋 전체 | 0,0 3×2 | 기본값은 매개변수 기본값(최근 30일)에서 |
| 선택기: 비교 기간 (결제일) | filter (Date range) | - | Parameter: `compare_range`. 비교 표 데이터셋에만 연결 | 3,0 3×2 | 기본값은 매개변수 기본값에서 |

WHEN cur_sales_metrics.refund_ratio IS NULL OR cmp_sales_metrics.refund_ratio IS NULL THEN '-' ELSE (CASE WHEN cur_sales_metrics.refund_ratio > cmp_sales_metrics.refund_ratio THEN '▲ ' WHEN cur_sales_metrics.refund_ratio < cmp_sales_metrics.refund_ratio THEN '▼ ' ELSE '' END) || format_number(ABS(cur_sales_metrics.refund_ratio - cmp_sales_metrics.refund_ratio) * 100.0, 1) || '%p' END AS change FROM cur_refund_metrics CROSS JOIN cur_sales_metrics CROSS JOIN cmp_refund_metrics CROSS JOIN cmp_sales_metrics ORDER BY sort_order

**`val_refund_by_reason`** — 사유별 환불금액 비중 막대와 상세 표

- 뷰: `refund_metrics` / 분석 기준: refund_reason / 지표: refund_amount, refund_quantity
- 위젯이 쓰는 열: refund_reason, refund_amount, refund_quantity, refund_amount_share

```sql
SELECT *, CAST(refund_amount AS DOUBLE) / SUM(refund_amount) OVER () AS refund_amount_share FROM (SELECT refund_reason, MEASURE(refund_amount) AS refund_amount, MEASURE(refund_quantity) AS refund_quantity FROM commerce_poc.serving.refund_metrics WHERE payment_date BETWEEN :date_range.min AND :date_range.max AND array_contains(:channels, channel_name) AND array_contains(:categories, category) AND array_contains(:products, product_name) GROUP BY ALL) AS base ORDER BY refund_amount DESC, refund_reason
```

## 9. 선택기 연결 방법

- 각 페이지 캔버스 맨 위에 선택기를 둔다(전역 필터 패널은 쓰지 않는다). Filter 위젯 → Add → 종류(Date range / Multiple values) 선택 → Parameter에 이름을 지정하고, 그 페이지 위젯이 쓰는 데이터셋 중 그 매개변수를 쓰는 것에 모두 연결한다.
- 다중 선택(`channels`, `categories`, `products`)은 Field에 위 선택지 데이터셋의 열을 지정한다.
- 비교 기간(`compare_range`)은 비교 표 데이터셋(`*_compare`)에만 연결한다.

## 10. 자주 하는 유지보수

| 하고 싶은 일 | 어디를 만지나 |
|---|---|
| 지표를 다른 것으로 바꾸기 | 데이터셋 SQL의 `MEASURE(...)`와 위젯의 Y/Value 열 |
| 상위·하위 N개만 보기 | 데이터셋 SQL 끝에 `LIMIT N` (하위는 `ORDER BY`를 ASC로) |
| 주별 → 일별 | 데이터셋의 `payment_week`를 `payment_date`로, 위젯 X 필드도 바꾼다 |
| 새 필터 추가(예: 결제수단) | 매개변수 `methods` 추가 → 데이터셋 WHERE에 `AND array_contains(:methods, method_name)` → 선택기 위젯 연결 |
| 새 위젯 추가 | 기존 데이터셋을 쓰거나, 새 데이터셋을 만들되 WHERE 조건을 같은 페이지 다른 데이터셋과 똑같이 맞춘다 |
| 같은 위젯을 다른 페이지에서 쓰기 | 위젯을 복사하고 데이터셋을 그 페이지 접두사(`sum_`/`mkt_`/`val_`)의 것으로 바꾼다 |
| 색·정렬·서식 | 위젯 설정만. 데이터셋은 건드리지 않는다 |
| 지표 정의 자체를 바꾸기 | 화면이 아니라 `03_serving/metric_views/metric_defs.py`와 명세 6.5절 (승인 필요) 후 `run_metric_views.py` 재실행 |

## 12. 알려진 한계
- 조회 기간 끝이 오늘이면 오늘은 하루가 다 차지 않아 증감이 낮게 나올 수 있다.
- 데이터가 2025-10-15부터라 비교 기간을 그 전으로 고르면 증감은 `실적이 없습니다.`로 보인다.
- 비교 표의 값은 쿼리에서 만든 문자열이라 정렬·합산에 쓸 수 없다 (숫자는 KPI 데이터셋에 있다).
- Lakeview는 한 위젯에 값 하나만 담고 폰트·카드 모양을 지정할 수 없어, 카드는 counter + 설명 글로, 증감은 비교 표로 만든다.
- CTE 구조의 `MEASURE()` 조회가 실패하면 오류 문장을 알려 주면 기간별 쿼리로 나눈다.
