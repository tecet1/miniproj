# 대시보드 화면 구성 가이드 (카드 5-G)

저장소의 `commerce_poc.lvdash.json`은 `build_dashboard.py`가 만든 개편안이다. **Databricks에서 열어 확인하지 못했다(미검증).** 필터 버전을 열었을 때 끊긴다는 이전 보고가 있어, 열리지 않으면 아래 3절로 화면에서 직접 구성한다. 데이터셋 SQL은 로컬 테스트(sqlite, 손계산 기대값)를 통과한 것과 같은 문장이지만, Spark에서 실행되는 것은 아직 확인하지 못했다.

## 1. 실행 순서 (Databricks)

1. 저장소를 커밋·푸시하고 Databricks Git folder에서 **Pull**한다.
2. Gold가 최신이 아니면 `02_pipeline/gold/run_gold.py`를 실행한다 (`check_gold` 통과 확인).
3. **`03_serving/metric_views/run_metric_views.py`를 반드시 다시 실행한다.** 두 Metric View에 `payment_week`(결제주) 분석 기준이 추가되었다. 다시 만들지 않으면 주별 데이터셋이 `payment_week` 열을 찾지 못해 실패한다. 실행 뒤 `check_metric_views` 결과가 `OK`(빈 목록)여야 한다.
4. 아래 SQL의 핵심을 SQL 편집기에서 먼저 시험한다: `SELECT payment_week, MEASURE(total_sales) FROM commerce_poc.serving.sales_metrics GROUP BY ALL ORDER BY 1` 이 월요일 날짜를 주마다 한 줄씩 내야 한다.
5. `03_serving/dashboards/commerce_poc.lvdash.json`을 열어 본다. 열리면 3-5절의 시험 항목만 확인한다. 안 열리면 3절부터 따라 한다.

## 2. 구성 요약

- 필터(전역): 채널(다중, 기본 전체), 카테고리(다중, 기본 전체), 조회 기간(결제일, 기본 최근 30일). 비교 기간은 읽기 전용 표시(`compare_period` 데이터셋).
- 판매 페이지: 큰 카드 3개(총판매금액, 순판매금액, 환불금액비율; 이전 기간·전년 동기 증감) + 작은 카드 5개(결제고객수, 객단가, 상품결제건수, 상품결제단가, 환불금액; 이전 기간 증감) + 채널별 총판매금액 주별 선 + 채널별 순판매금액 비중 막대 + 환불금액비율 주별 선 + 결제수단·카테고리별 총판매금액 막대 + 채널별 지표 표.
- 환불 페이지: 큰 카드 3개(환불금액, 환불수량, 환불금액비율) + 사유별 환불금액 막대 + 채널별 환불금액비율 막대 + 결제일별(원결제일) 환불금액 주별 선 + 사유별 상세 표.
- 증감 표시: `▲ 12.3%`, `▼ 5.0%`, 변화 없음 `0.0%`. 비교 기간에 상품결제건수가 0이면 `실적이 없습니다.`, 비교값이 0이거나 없으면 `-`. 상태 색(초록·빨강)은 쓰지 않는다.
- 첫 주·마지막 주는 조회 기간 경계로 부분 주일 수 있고, 환불 추이의 최근 주는 환불 접수 중이라 낮을 수 있다(차트 제목에 적어 두었다).

## 3. 화면에서 직접 구성

### 3-1. 데이터셋 매개변수

모든 데이터셋에 같은 이름·형식의 매개변수를 만든다 (이름이 같아야 전역 필터 하나가 데이터셋 전체에 걸린다). `compare_period`는 `date_range`만 쓴다.

| 매개변수 | 유형 | 기본값 |
|---|---|---|
| `date_range` | 날짜 범위 | `now-30d/d` ~ `now/d` (상대 날짜) |
| `channels` | 다중 선택 문자열 | 자사몰, 종합 오픈마켓, 스포츠 전문몰 (전체) |
| `categories` | 다중 선택 문자열 | 가방, 신발, 액세서리, 의류, 캠핑·등산 장비 (전체) |

### 3-2. 데이터셋 SQL (그대로 붙여 넣는다)

**`compare_period`**

```sql
SELECT date_format(date_sub(:date_range.min, datediff(:date_range.max, :date_range.min) + 1), 'yyyy-MM-dd') || ' ~ ' || date_format(date_sub(:date_range.min, 1), 'yyyy-MM-dd') AS prev_period, date_format(add_months(:date_range.min, -12), 'yyyy-MM-dd') || ' ~ ' || date_format(add_months(:date_range.max, -12), 'yyyy-MM-dd') AS yoy_period
```

WHEN cur_sales_metrics.refund_ratio IS NULL OR prev_sales_metrics.refund_ratio IS NULL OR prev_sales_metrics.refund_ratio = 0 THEN '-' ELSE (CASE WHEN cur_sales_metrics.refund_ratio > prev_sales_metrics.refund_ratio THEN '▲ ' WHEN cur_sales_metrics.refund_ratio < prev_sales_metrics.refund_ratio THEN '▼ ' ELSE '' END) || format_number(ABS(cur_sales_metrics.refund_ratio - prev_sales_metrics.refund_ratio) * 100.0 / ABS(prev_sales_metrics.refund_ratio), 1) || '%' END AS refund_ratio_prev, CASE WHEN yoy_sales_metrics.item_count IS NULL OR yoy_sales_metrics.item_count = 0 THEN '실적이 없습니다.' WHEN cur_sales_metrics.refund_ratio IS NULL OR yoy_sales_metrics.refund_ratio IS NULL OR yoy_sales_metrics.refund_ratio = 0 THEN '-' ELSE (CASE WHEN cur_sales_metrics.refund_ratio > yoy_sales_metrics.refund_ratio THEN '▲ ' WHEN cur_sales_metrics.refund_ratio < yoy_sales_metrics.refund_ratio THEN '▼ ' ELSE '' END) || format_number(ABS(cur_sales_metrics.refund_ratio - yoy_sales_metrics.refund_ratio) * 100.0 / ABS(yoy_sales_metrics.refund_ratio), 1) || '%' END AS refund_ratio_yoy FROM cur_refund_metrics CROSS JOIN cur_sales_metrics CROSS JOIN prev_refund_metrics CROSS JOIN prev_sales_metrics CROSS JOIN yoy_refund_metrics CROSS JOIN yoy_sales_metrics

### 3-4. 전역 필터

필터 페이지에 채널(다중 선택, 선택지 `channel_options`), 카테고리(다중 선택, 선택지 `category_options`), 조회 기간(날짜 범위)을 만들고, 각 필터를 해당 매개변수를 쓰는 모든 데이터셋에 연결한다.

### 3-5. 화면에서 시험할 항목 (모두 미검증, 안 되면 가까운 형태로 대체)

| 항목 | 기대 | 안 될 때 |
|---|---|---|
| 채널 색 고정 | 자사몰 `#2a78d6`, 오픈마켓 `#eb6834`, 스포츠 전문몰 `#1baf7a` | 기본 색을 쓰고 범례로 채널을 구분한다. 청록은 배경 대비가 낮으므로 범례·직접 라벨을 둔다 |

## 4. 알려진 한계

- 조회 기간 끝이 오늘이면 오늘은 하루가 다 차지 않아 증감이 낮게 나올 수 있다.
- 데이터가 2025-10-15부터라 조회 기간이 1년 전으로 가면 전년 동기는 `실적이 없습니다.`로 보인다.
- 증감 문장은 쿼리에서 만든 문자열이라 정렬·합산에 쓸 수 없다. 숫자 증감률이 필요하면 별도 요청한다.
- 한 쿼리에서 Metric View를 여러 번 `MEASURE()`로 조회하는 CTE 구조는 Databricks에서 확인하지 못했다. 실패하면 오류 문장을 알려 주면 기간별 쿼리로 나눈다.
