# 스마트스토어 분석 화면 벤치마킹

- 기간·채널·상품 필터, 핵심 지표 카드, 추이, 상세표의 구성을 참고한다.
- 거래 이벤트로 계산 가능한 최소 지표만 사용한다. 스마트스토어의 공식 집계 정의를 재현했다고 주장하지 않는다.
- 현재 단계의 산출물은 설계 참고 자료다. 구현은 Bronze·Silver 검증 후 M4에서 진행한다.

## 검토한 자료

- `01_filters.png`, `02_metrics.png`, `03_trends.png`, `04_details.png`는 사용자가 제공한 판매분석 화면이다.
- `summary_container.txt`는 별도의 요약 화면 HTML이다. 화면 구조와 문구만 참고하며 실행하거나 스크립트를 로드하지 않는다.

판매분석 화면의 카드: 판매금액(총), 판매금액(순), 환불금액비율, 상품결제건수, 상품결제단가. 상세표에는 상품별 환불건수와 환불건수비율도 보인다.

요약 HTML의 카드: 판매금액(총), 방문수, 상품결제건수, 구매전환율, 환불금액비율, 결제고객수, 객단가, 상품결제단가. 유사 스토어 비교와 시그널 안내도 포함한다.

카드 이름과 화면만으로 실제 산식·상품결제건수의 단위·환불의 날짜 귀속을 확정할 수 없다. 아래는 우리 PoC의 제안 정의다.

## 최소 화면 구성

- 상단: 기간, 채널, 공통 SKU 필터. 채널 원본 SKU도 상세표에서 확인할 수 있게 한다.
- 중단: 카드 5개와 일별 금액 추이. 하단: 일자·채널·SKU 상세표.

초기 카드는 결제액, 환불액, 순결제액, 환불금액비율, 결제 주문 수다. 기존 계획의 핵심 지표 3~5개 범위 안에서 구성한다. 상품별 순결제액 순위는 같은 지표를 재사용하는 상세표 정렬로 시작한다.

1일/7일/30일/직접 선택, 비교 기간, 일/주/월 전환은 후속 UI 후보다. 먼저 하나의 기간 필터와 일별 추이를 구현한다. 카테고리·브랜드는 현재 SKU 매핑에 속성이 없어 상품 마스터가 필요하다. 배송 유형은 현재 프로젝트 범위에서 제외한다.

## PoC 지표 계약 제안

- KRW, 상품 금액만 포함하고 세금·배송비·할인은 제외한다.
- 결제와 환불은 각 업무 발생 시각을 KST로 변환한 날짜에 귀속한다. 수집·적재 날짜를 사용하지 않는다.

| 지표 | 정의 | 현재 A fixture 기대값 |
|---|---|---:|
| 결제액 | 기간 내 PAYMENT_SUCCEEDED의 paid_amount 합계 | 80,000원 |
| 환불액 | 기간 내 REFUND_COMPLETED의 refund_amount 합계 | 25,000원 |
| 순결제액 | 결제액 - 환불액 | 55,000원 |
| 환불금액비율 | 환불액 / 결제액 × 100, 결제액 0이면 NULL | 31.25% |
| 결제 주문 수 | 기간 내 성공 결제가 있는 (channel_id, order_id)의 고유 수 | 1건 |

위 수치는 로컬의 합성 이벤트 여섯 개로 검산한 기대값이다. 실제 스마트스토어 실적이나 Databricks 실행 결과가 아니다.

현재 fixture의 결제 주문은 1건, 결제 상품 라인은 2개, 결제 상품 수량은 3개다. 이 셋을 '상품결제건수'로 혼용하지 않는다. 상품 지표를 추가할 때에는 '결제 상품 수량', '상품 1개당 평균 결제금액'처럼 단위를 밝힌다.

발생일 기준 환불금액비율은 같은 기간 결제의 코호트 환불률이 아니다. 과거 결제의 환불이 해당 기간에 발생하면 100%를 초과할 수 있으며 순결제액이 음수일 수도 있다. 이를 일반적인 데이터 오류로 처리하지 않는다. 주문일 코호트 분석은 현재 최소 화면에서 추가하지 않는다.

미결제 취소 50,000원은 결제액에 포함되지 않았으므로 순결제액에서 다시 빼지 않는다. 결제 실패 요청액도 결제액에 넣지 않는다.

## 상세표와 Gold 설계 영향

- 상세표 후보 grain은 (business_date, channel_id, sku_id)이며 거래는 먼저 해당 지표의 grain에서 정규화한다.
- 주문·결제·환불 원본을 그대로 이어 붙이는 조인으로 금액이 중복되지 않게 한다.

상품별 결제액은 성공 결제의 주문 상품에 연결한다. 현재 계약은 주문당 한 번의 전체 성공 결제, 상품 합계와 결제액 일치이므로 원래 주문 라인 금액으로 귀속 가능하다. 일부 결제·할인을 지원하는 일반적인 결제 배분 알고리즘을 구현한 것으로 표현하지 않는다.

환불액은 환불 항목별 금액을 SKU에 귀속한다. 현재 A fixture에서 SKU-001의 결제액/환불액/순결제액은 50,000/25,000/25,000원, SKU-002는 30,000/0/30,000원이다.

상품별 결제 주문 수는 여러 SKU에 동일 주문이 나타날 수 있으므로 SKU별 건수를 더해 전체 주문 수로 사용하지 않는다. 고객 수와 비율도 일별 값이나 그룹별 값을 단순 합산하지 않는다. 비율은 조회한 범위의 분자·분모를 다시 집계한다.

## 빈 값과 비교 기간

- 분모가 0이거나 비교 기준이 없으면 비율·증감률을 '-'로 표시한다.
- 거래가 0인 구간과 데이터 적재가 확인되지 않은 구간을 구분한다.

이전 기간 값이 0이면 증감률을 0%나 100%로 임의 표시하지 않는다. 환불액과 순결제액에는 음수와 0 기준의 의미가 있으므로 증감률보다 절대 금액 변화부터 제공할 수 있다. 일별 차트의 비율을 평균내어 기간 비율로 사용하지 않는다.

## 제외와 확인 필요

- 방문수·구매전환율·유사 스토어 비교는 현재 거래 원본만으로 계산할 수 없다.
- 고객 분석·카테고리·브랜드·상품결제단가는 지표 정의와 추가 데이터 필요를 먼저 확인한다.

방문·전환 이벤트나 다른 판매자의 기준 데이터 생성은 이번 최소 범위에 추가하지 않는다. 고객 수·객단가는 채널 내 고객 식별자의 품질을 확인하면 계산 후보가 될 수 있지만, 채널 간 동일 고객 판별은 현재 계약에 없다.

범위 이탈 경고: 스마트스토어 전체 기능을 재현하기 위해 방문 생성기·고객 통합·경쟁 스토어 데이터·복잡한 매핑을 새로 구현하면 A→Bronze→Silver 완료가 지연된다. 최소 대안은 현재 거래 지표 5개와 기간·채널·SKU 조회다.
