# 계획 01. 이벤트 생성기와 Functions → Event Hubs 전송

## 목표

고정 시나리오에서 채널별 원본 이벤트를 생성하고, HTTP → Azure Functions → Event Hubs 경로로 전송해 도착 건수를 확인한다.

## 입력 / 산출물

- 입력: `01_contracts/contracts/` 시나리오·SKU 명세(`scenarios.md`, `sku_spec.md`), 이벤트 명세
- 산출물
  - `01_contracts/data/scenarios/scenarios.json`, `01_contracts/data/reference/skus.json`
  - `01_contracts/data/fixtures/{A,B,C}/events.jsonl` (채널당 24건, 봉투 형식)
  - `01_contracts/data/fixtures/expected/` 독립 기대값 (건수·금액·지표)
  - `01_contracts/src/` 생성기(채널별 변환 a·b·c, 실행 진입점), 기대값 계산 스크립트
  - `02_pipeline/ingestion/` `function_app.py`, `send_events.py`, `requirements.txt`, `host.json`
  - `02_pipeline/tests/contracts`, `02_pipeline/tests/ingestion`
- 흐름도: `02_pipeline/ingestion/Ingestion_흐름도.pptx`

## 설계 결정

- 봉투 형식: `{"channel":"A","received_at":"…","payload":"<원본 본문 문자열 그대로>"}`
- 경로: `POST /api/events/{channel}`. A·B·C 외 채널은 400, 성공은 202. Function은 payload를 해석하지 않는다.
- 파티션 키 없음(라운드로빈). 순서는 Silver가 이벤트 시각으로 처리한다.
- 인증: Function 키(`x-functions-key`, 환경 변수 `FUNCTION_KEY`), Event Hubs는 Managed Identity(Data Sender). Key Vault는 범위 밖.
- 송신 실패 시 재시도한다. 중복은 Silver에서 `channel + event_id`로 제거한다.
- 인프라: 허브 `commerce-events`(파티션 2개), 소비자 그룹 생성 완료. Databricks 읽기 자격은 Bronze 적재 계획에서 확인한다.

## 단계

0. 인프라 확인 (완료 · 사용자 확인): Function App, 관리 ID, 역할, 키, 소비자 그룹, 배포 워크플로
1. `scenarios.json`, `skus.json` 작성 (명세와 일치)
2. 채널별 변환과 생성기 작성, `events.jsonl` 생성
3. 기대값 계산 스크립트로 `expected` 생성 (파이프라인 코드와 로직 공유 금지)
4. Function 작성 (봉투 검증 → Event Hubs 전송)
5. 송신기 작성 (`events.jsonl` → HTTP POST, 재시도)
6. GitHub Actions로 배포 후 원격 실행
7. 도착 확인 스크립트로 소비자 그룹 `verify`에서 건수·내용 대조

## 완료 조건

- 같은 입력으로 생성기를 반복 실행해도 `events.jsonl`이 동일하다 (해시 일치).
- 채널별 24건, 3채널 합계 72건. 중복(S19)은 같은 이벤트가 2건 포함된다.
- 채널별 원본 형식이 명세와 일치한다 (A: ISO 8601 UTC, B: epoch ms, C: KST 문자열).
- 3종 격리 변형(S21)이 채널마다 1건씩 포함된다 (합계 9건).
- 송신 후 Event Hubs에서 읽은 건수가 72건이고, 봉투의 payload가 원본과 바이트 단위로 같다.
- A·B·C 외 채널은 400을 반환하고 Event Hubs에 쓰이지 않는다.
- 저장소에 키·연결 문자열이 없다.

## 검증 방법

- 생성기: `python .\01_contracts\src\<생성기>.py` 후 해시 비교 (파일명 확정 후 AGENTS.md 표 갱신)
- 로컬 테스트: `python -m unittest discover -s .\02_pipeline\tests -v`
- 원격: 배포 후 송신기 실행, 도착 확인 스크립트가 출력한 건수를 `expected`와 비교
- 기대값은 구현 통과를 위해 수정하지 않는다.

## 범위 밖 (이 계획에서 하지 않음)

- Bronze 적재, Silver 변환, 이상·미결 목록, 대량 부하 세트, 스키마 버전 처리, 실행 모니터링

보류 — 인프라 확인 완료, 구현 시작 전. 단계 6·7은 원격 실행 전까지 '미검증'으로 기록한다.
