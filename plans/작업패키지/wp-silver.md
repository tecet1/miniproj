# WP-Silver: Spark 네이티브 전환과 집합 검사 이전

## 목표
Silver의 행 단위 UDF 변환을 Spark 표현식으로 바꾸고, 기대값이 필요 없는 집합 단위 검사를 선언형 규칙으로 옮겨 결과를 기록한다.

## 입력 / 산출물
- 입력: `plans/07_오케스트레이션과_품질_규칙.md` 카드 7-B·7-C, `02_pipeline/quality/rules.json`(카드 7-A, 완료), 현재 `02_pipeline/silver/`
- 산출물: `02_pipeline/silver/` 변환·검증 코드, `02_pipeline/quality/` 규칙 연결, 결과 테이블 `commerce_poc.quality.results`의 기록 로직, 테스트

## 완료 조건
- 7-B: 픽스처 72건에서 `expected.json`과 건수·분포·격리 건수·사유 코드가 이전과 같다. 덤프 기대값(`expected_dump.json`)과도 같아야 하지만, 덤프가 재설계 중이므로 **병합 시점 main의 `expected_dump.json` 기준으로 다시 돌린다**(그 전에는 현재 파일 기준 결과를 '잠정'으로 적는다).
- 7-C: 규칙이 위반하면 결과 행에 규칙 이름·단계·위반 건수가 남는다. 규칙을 일부러 어기게 한 데이터에서 위반을 잡는다.

## 검증 방법
- `python -m unittest discover -s .\02_pipeline\tests\silver -v`와 quality 관련 테스트.
- 변이 테스트: 변환식 하나를 일부러 틀려 실패하는지 확인한다.
- Databricks 실행은 사용자 확인 전까지 '미검증'이다.

## 소유 경로
`02_pipeline/silver/`, `02_pipeline/quality/`, `02_pipeline/tests/silver/`와 quality 관련 테스트 폴더. `bronze/`, `gold/`, `04_experiments/`, `01_contracts/`는 수정하지 않는다.

## 범위 밖
7-D(증분 검증)는 이 WP가 끝난 뒤 별도로 시작한다. 스키마 버전 처리와 상품 SCD는 범위 밖이다.

## 공통 규칙 (모든 WP)

- 먼저 `AGENTS.md`, `plans/결정_로그.md`, `plans/09_병렬_작업_분배.md`를 읽는다. 충돌 시 우선순위는 최신 사용자 지시 > AGENTS.md > plans/ > 이 파일이다.
- **소유 경로 밖은 수정하지 않는다.** 밖의 변경이 필요하면 멈추고 보고한다. 다른 WP가 소유한 파일을 고치지 않는다.
- 변경안(파일, 기대값, 영향, 시간)을 먼저 제안하고 승인 전에는 수정하지 않는다.
- 독립 기대값(`expected*`, 픽스처)을 구현·테스트 통과를 위해 고치지 않는다. 테스트를 삭제·완화하지 않는다.
- 새 테스트는 코드를 일부러 망가뜨려 실패하는지까지 확인한다.
- 로컬 테스트 통과는 Databricks 성공이 아니다. 원격 확인 전에는 '미검증'으로 적는다.
- 전체 테스트에서 `regenerated_fixtures_are_identical`(채널 A·B·C) 3건은 이미 실패 중이다(CRLF 픽스처와 LF 재생성 비교). 이 WP의 변경으로 늘어난 실패와 구분해 보고하고, 이 3건은 고치지 않는다.
- 결정이 생기면 `plans/결정_로그.md` 맨 아래에 한 줄을 추가한다(기존 행은 고치지 않는다).
- UTF-8, 기존 CRLF 유지, BOM 없음. 비밀 값은 넣지 않는다.
- 작업 보고는 목표 / 입력·산출물 / 완료 조건 / 검증 방법 / 상태(완료·미검증·보류)로 쓴다. 확인한 범위와 못 한 범위를 구분한다.
- 작업이 한 단계 끝날 때마다 이 파일의 `## 상태` 절을 갱신한다. 형식은 한 줄이다: `상태: 진행중|완료|미검증|보류 / 갱신: YYYY-MM-DD HH:MM / 지금: <한 줄> / 다음: <한 줄> / 막힘: <없음|내용>`. 집계 명령이 이 절만 읽으므로 다른 내용을 섞지 않는다.
