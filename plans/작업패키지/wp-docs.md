# WP-문서: 산출물 정리와 지침 갱신

## 목표
`report/산출물_정리.md`와 `CLAUDE.md`를 저장소의 현재 상태와 맞추고, 요구사항 대비 한계를 정직하게 적는다.

## 입력 / 산출물
- 입력: `report/산출물_정리.md`, `CLAUDE.md`, `plans/결정_로그.md`, `plans/05`~`09`, 요구사항 슬라이드(`plans/6주차_발표자료_이성우_v4.pdf` 6·9·12·13쪽)
- 산출물: 수정된 `report/산출물_정리.md`, `CLAUDE.md`, 슬라이드 수정 항목 메모

## 수정 항목
1. 전체 흐름 다이어그램에서 Genie가 **Gold와 Metric View를 모두** 읽도록 고친다(계획 08 결정).
2. 결제주 "확인" 표기: 결제주 Spark 식 `date_sub(payment_date, weekday(payment_date))`의 Databricks 실제 결과는 **미검증**이다(계획 05 카드 5-G). 로컬은 sqlite에 같은 이름 함수를 등록해 실행한 것이다.
3. Gold·Metric View의 "사용자 보고" 확인과 독립 대조 확인을 표에서 구분한다.
4. "요구사항 대비 한계" 절을 추가한다: 상품 15개(요구 약 1,500개, 이번에 충족하지 않음), 일 5,000건 규모(재설계 중), 5분 이내 반영(상시 스트리밍 전, 미측정), 취소·주문 지표와 시간대 드릴다운(지표 명세에 없음, 결정 대기). 단정하지 않고 "미검증"과 "충족하지 않음"을 구분한다.
5. 발표 슬라이드 12·13쪽의 ADLS Landing, 채널 B 타이머 조회, 채널 C 파일 수신은 구현(세 채널 모두 Event Hubs)과 다르다. 고칠 항목 메모만 남긴다(PDF 자체는 수정하지 않는다).
6. `CLAUDE.md`의 "현재 단계"를 갱신한다: 계획 07(작업 카드), 08, 09, 5-G, 덤프 재설계, 병렬 작업 체계를 반영한다. `@AGENTS.md` 임포트 줄은 그대로 둔다.
7. 폴더명·경로는 실제 저장소 기준으로 쓴다(예: `01_contracts/data_fixtures/`).

## 완료 조건
- 위 7개 항목이 반영되고, 확인되지 않은 내용을 완료로 적은 곳이 없다.
- 문서의 숫자(건수, 금액, 상태)는 `plans/`와 결정 로그의 출처와 같다.

## 검증 방법
- 수정한 문장마다 근거 문서를 대조해 목록으로 보고한다. 코드나 계획 문서의 상태는 바꾸지 않는다.

## 공통 규칙 (모든 WP)

- 먼저 `AGENTS.md`, `plans/결정_로그.md`, `plans/09_병렬_작업_분배.md`를 읽는다. 충돌 시 우선순위는 최신 사용자 지시 > AGENTS.md > plans/ > 이 파일이다.
- **소유 경로 밖은 수정하지 않는다.** 밖의 변경이 필요하면 멈추고 보고한다. 다른 WP가 소유한 파일을 고치지 않는다.
- 변경안(파일, 기대값, 영향, 시간)을 먼저 제안하고 승인 전에는 수정하지 않는다.
- 독립 기대값(`expected*`, 픽스처)을 구현·테스트 통과를 위해 고치지 않는다. 테스트를 삭제·완화하지 않는다.
- 새 테스트는 코드를 일부러 망가뜨려 실패하는지까지 확인한다.
- 로컬 테스트 통과는 Databricks 성공이 아니다. 원격 확인 전에는 '미검증'으로 적는다.
- 전체 테스트에서 `regenerated_fixtures_are_identical`(채널 A·B·C) 3건은 이미 실패 중이다(CRLF 픽스처와 LF 재생성 비교). 이 WP의 변경으로 늘어난 실패와 구분해 보고하고, 이 3건은 고치지 않는다.
- 결정이 생기면 `plans/결정_로그.md` 맨 아래에 한 줄을 추가한다(기존 행은 고치지 않는다).
- UTF-8, 기존 CRLF 유지, BOM 없음. 비밀 값은 넣지 않는다.
- 작업 보고는 목표 / 입력·산출물 / 완료 조건 / 검증 방법 / 상태(완료·미검증·보류)로 쓴다. 확인한 범위와 못 한 범위를 구분한다.
- 작업이 한 단계 끝날 때마다 이 파일의 `## 상태` 절을 갱신한다. 형식은 한 줄이다: `상태: 진행중|완료|미검증|보류 / 갱신: YYYY-MM-DD HH:MM / 지금: <한 줄> / 다음: <한 줄> / 막힘: <없음|내용>`. 집계 명령이 이 절만 읽으므로 다른 내용을 섞지 않는다.
